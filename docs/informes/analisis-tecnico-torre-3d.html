Informe técnico de Torre 3D

El motor de cálculo está separado de la interfaz y tiene una base sólida de pruebas. Las primeras correcciones deben proteger la importación y el guardado, hacer reproducible el cálculo entre computadoras y garantizar que la versión web arranque sin conexión.

Hallazgos y soluciones recomendadas

Prioridad alta

1. Un archivo importado puede ejecutar JavaScript

En Chrome, un nombre de nivel de un JSON de prueba ejecutó JavaScript al abrir «Rototrasl. → En 3D». El rótulo llega a innerHTML. En la versión web, ese código podría acceder al proyecto activo, a las copias guardadas y a la URL de sincronización con Sheets si está configurada.

Solución
Crear los rótulos con nodos DOM y asignar nombres e identificadores con textContent. Revisar los usos de innerHTML que interpolan datos de proyectos, planillas y tablas remotas.
Verificación
Abrir en Chrome un proyecto con etiquetas y atributos HTML como texto. Deben verse literalmente en rótulos y medidas, sin ejecutar código.

Rótulos 3D · Panel de medidas

2. Un proyecto inválido puede reemplazar el guardado activo

La validación inicial comprueba la versión y algunos campos superiores. Una prueba con niveles: [null] llegó al guardado automático. Si falla un recálculo, el estado puede conservar datos del cálculo anterior junto con el error. Los fallos del guardado automático se descartan en silencio.

Solución
Usar un lector común que valide y migre JSON, datos reconstruidos desde Excel, Sheets y almacenamiento local antes de activar el proyecto. Modelar el cálculo como vigente, pendiente o fallido y vincularlo a la revisión del modelo. Indicar si falló el guardado y ofrecer descargar el proyecto activo.
Verificación
Probar proyectos con niveles o muros inválidos, referencias rotas y almacenamiento lleno. Un error de importación debe preservar el último proyecto válido. Las vistas y exportaciones deben detectar resultados vencidos.

Validación de entrada · Cálculo y persistencia

3. Sheets permite escrituras amplias y puede dejar cambios parciales

Este punto es de prioridad alta si se usa Sheets para entregas. El instructivo configura acceso público y ejecuta el script como propietario. El servidor acepta hojas, rangos y fórmulas de la petición, y toma el bloqueo al marcar la versión, después de escribir. Google documenta que getDocumentLock() devuelve null en una app web.

Solución
Restringir el acceso a usuarios autorizados, abrir la planilla por ID configurado del lado del script y permitir únicamente las tablas, celdas y operaciones previstas. Validar el paquete completo antes de escribir, tomar un bloqueo de script que cubra la operación y exigir la revisión remota esperada. En el cliente, serializar los envíos y cancelar o descartar las respuestas de una conexión reemplazada.
Verificación
En una planilla de prueba, enviar un paquete fuera de los rangos permitidos, simular dos editores y provocar un fallo a mitad de escritura. Verificar el rechazo, la detección del conflicto y el tratamiento de los cambios parciales.

Escritura y bloqueo en Apps Script · Cliente de sincronización · Documentación de Google

4. La versión web puede fallar sin red después de la primera visita

En un perfil nuevo de Chrome, la primera visita dejó en caché el HTML, el manifiesto y los íconos. La recarga sin conexión falló porque faltaban el JavaScript y el CSS. La activación también elimina las cachés del mismo origen que tengan un nombre diferente al suyo. Eso puede afectar otros proyectos bajo el mismo dominio de GitHub Pages.

Solución
Generar en el build un manifiesto de precaché con los recursos requeridos. Usar un prefijo y una versión propios del sitio y limpiar solo sus versiones anteriores. Indicar cuándo terminó la descarga de los recursos necesarios para trabajar sin conexión.
Verificación
Abrir la app con un perfil limpio, esperar la instalación, cortar la red y volver a abrir. Probar también una actualización de versión y comprobar que se conservan las cachés ajenas.

Service worker · Sitios de proyecto en GitHub Pages

Prioridad media-alta

5. El mismo archivo puede producir resultados diferentes

El JSON guarda el modelo. El motor y el método de armado se leen de la configuración del navegador. La exportación a Excel, además, cambia temporalmente el motor global durante operaciones asíncronas. Con el mismo JSON del ejemplo asimétrico, cambiar solo de motor alteró la carga total de viento A de 129,55 t a 125,81 t. Con el mismo motor, cambiar el método llevó ΣJ del viento B de 7,233 a 7,748 m⁴.

Solución
Guardar un JSON versionado con el modelo y la configuración del cálculo. Pasar esta configuración explícitamente al motor. Exportar y sincronizar desde una copia fija del proyecto, los parámetros y el resultado de esa misma revisión.
Verificación
Abrir el archivo en dos perfiles limpios con preferencias locales distintas. Con la versión de fórmulas registrada, comparar valores de ambos vientos, asignación de piezas y estados de los controles.

Motores y métodos · Preferencias locales · Exportación Excel

6. «Todo verifica» puede dar una impresión más amplia que los controles

El resumen puede indicar «Todo verifica» aunque la tensión admisible del suelo sea un dato informativo que depende del estudio de suelos. El motor también distingue verificaciones, avisos y cuestiones que requieren revisión de la cátedra.

Solución
Describir el alcance como «Verifican los controles calculados» y mostrar los controles informativos o los datos pendientes por separado. Identificar en pantalla y en los informes la fuente elegida, el motor y el método.
Verificación
Revisar un caso con controles calculados satisfactorios y datos informativos. El resumen y el informe deben indicar qué quedó sujeto a revisión.

Resumen de estado · Criterios y controles

7. Las plantillas de la cátedra se distribuyen públicamente

Las dos plantillas de Excel están disponibles como recursos de GitHub Pages y forman parte de la distribución. La licencia del repositorio excluye el material de la cátedra.

Solución
Verificar y documentar el permiso de redistribución para cada plantilla. Si alguna requiere distribución restringida, permitir que el estudiante aporte su copia al exportar y ajustar qué recursos se incluyen en ambos builds públicos.
Verificación
Revisar el inventario del artefacto web y del HTML autocontenido contra los permisos confirmados.

Licencia del repositorio · Plantillas del código fuente

Prioridad media

8. La validación y la publicación pueden aislarse mejor

GitHub Actions instala desde el lockfile, ejecuta las pruebas y construye ambas variantes. El workflow se activa al actualizar main o manualmente, comparte permisos de Pages con el job de build y referencia las acciones por etiqueta.

Solución
Ejecutar pruebas, chequeo de tipos y builds también en los pull requests. Reservar pages: write e id-token: write para el job de despliegue y fijar las acciones a commits verificados.
Verificación
Un pull request debe validar ambas variantes sin credenciales de publicación. La actualización de main debe publicar únicamente cuando termine el build correspondiente.

Workflow de Pages · Guía de despliegue de GitHub

9. Hay dos copias del HTML descargable con contenido diferente

La versión de descargar/ y la publicada difieren en bytes. Ambas pesan alrededor de 4,7 MB, mientras que el README indica unos 0,8 MB.

Solución
Distribuir el HTML que genera CI desde un enlace único por versión. Mostrar el identificador de compilación en la app y actualizar el README con la ubicación y el tamaño reales.
Verificación
Descargar el archivo desde el enlace documentado, abrirlo localmente sin red y cotejar su versión con el build publicado.

Instrucciones de descarga · HTML publicado

10. Vite y Vitest tienen avisos para sus servidores de desarrollo y prueba

La auditoría del lockfile detectó avisos aplicables a las versiones instaladas. Los ejemplos citados afectan al servidor de desarrollo de Vite y al servidor de API de Vitest cuando está habilitado.

Solución
Actualizar Vite, Vitest y sus dependencias relacionadas a versiones compatibles con las correcciones. Revisar los avisos según el entorno en que se usan y verificar la versión web y el HTML clásico.
Verificación
Repetir la auditoría y ejecutar las pruebas, los builds y una apertura del HTML autocontenido.

Lockfile · Aviso de Vite · Aviso de Vitest

11. El estado compartido concentra demasiadas responsabilidades

Estado administra el modelo, historial, persistencia, vistas y cálculo. main.ts coordina archivos, navegación y sincronización. El editor de planta mezcla herramientas de dibujo y manejo del DOM. En proyectos grandes, serializar una copia completa por edición y recalcular en vivo son puntos a medir.

Solución
Separar de forma incremental las ediciones del modelo, el historial y la persistencia, el cálculo derivado y el estado visual. Extraer herramientas del editor al modificarlas. Medir arrastre, guardado y cálculo con una torre grande antes de introducir procesamiento en segundo plano o historial por operaciones.
Verificación
Comprobar que abrir, editar, deshacer, rehacer y exportar conservan su comportamiento. Medir la latencia antes y después con el mismo proyecto y equipo.

Estado de la aplicación · Punto de entrada · Editor de planta

Guardado y proyecto portable

El guardado automático mantiene un proyecto activo en el navegador. «Mis proyectos» conserva hasta 40 copias, con un máximo de 5 automáticas. Para trasladar el modelo se descarga un JSON. Excel permite otra vía de intercambio: el libro generado incluye tablas «T3D …» y una copia del JSON. Al reabrirlo, las tablas tienen prioridad para recuperar las ediciones hechas en la planilla.

Composición, tipos y clases

Torre 3D es una aplicación web educativa para modelar edificios en torre y estudiar su respuesta al viento. Usa TypeScript, HTML y CSS, SVG en planta y Three.js para el 3D. El motor de src/engine/ opera sobre interfaces y funciones independientes del DOM. src/ui/ organiza las vistas y el editor, src/xlsx/ lee y escribe las planillas y src/sync/ se ocupa de Sheets. Esta estructura permite probar el cálculo por separado y serializar el modelo como datos simples.

TypeScript usa strict. El tipo Muro reúne varias geometrías con atributos opcionales. Por ejemplo, admite un muro declarado como perfil sin su geometría y el motor lo interpreta como tabique. Conviene usar una unión discriminada en el modelo interno, con los atributos obligatorios de cada geometría, y resolver la compatibilidad con los archivos antiguos en el lector.

ClaseEvaluación y mejora
PrismaEncapsula el estado geométrico y actualiza los buffers durante la animación. Declarar readonly para las referencias a malla y bordes si conservan su identidad.
HojaAgrupa celdas, gráficos e imágenes y produce XML. Modelar texto y fórmulas como variantes explícitas. Hoy una cadena que empieza con = se exporta como fórmula.
SincroSheetsAdministra temporizadores, peticiones y revisión remota, con fetch inyectable para pruebas. Serializar escrituras y controlar el ciclo de vida de la conexión, como se detalla en el punto 3.
EstadoEl singleton simplifica la comunicación entre vistas, pero sus atributos públicos y mutables dificultan controlar cuándo se guarda y recalcula. Encauzar las mutaciones del modelo por operaciones explícitas y separar la selección, el historial y el resultado derivado. Véase el punto 11.
